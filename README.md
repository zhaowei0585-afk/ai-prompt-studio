# 映序 · AI 提示词工作台

一个本地运行的中文创作工作台，提供 **AI 漫剧 / AI 美女** 两个独立 Tab，管理提示词、参考素材和生成结果。

| Tab | 使用流程 | 使用说明书 |
|---|---|---|
| AI 漫剧 | 素材 → 剧本分镜 → 角色参考 → 图片词 → 视频词 → 回填与复盘 | [AI 漫剧使用说明](docs/04-drama-manual.md) |
| AI 美女 | 选人物与玩法 → 生成提示词 → 平台生成并回填；视频可选 | [AI 美女使用说明](docs/05-beauty-manual.md) |

工作台负责写提示词与留档；你复制到常用公开 AI 平台生成，再回填结果。ComfyUI 仍可选用，不要求接入生图或视频 API。页面侧栏的「使用说明书」会打开当前 Tab 对应的手册。

## 启动

安装 **Python 3.9 或以上**，无需安装 Python 包、Node.js 或 GPU 模型。

- Windows：双击 `start.bat`。
- macOS：双击 `start.command`；如果权限不足，在终端执行 `sh start.command`。
- Linux / 通用启动：在项目目录运行 `python3 studio.py`；Windows 也可以运行 `py -3 studio.py`。

浏览器自动打开 **http://127.0.0.1:8765**。保持终端窗口打开，按 `Ctrl+C` 退出。

```bash
# 端口冲突时
python3 studio.py --port 8766
# 自定义数据目录，不自动打开浏览器
python3 studio.py --data-dir /path/to/studio-data --no-browser
```

第一次打开，可以点击 **「打开原创示例」**，查看《雨夜失物》三个相互关联的镜头。示例只有原创文字与提示词草稿，没有实际参考图和生成视频。

## 从零走通一集

1. **素材与定位**：导入小说、漫画或 TXT/Markdown，注明本次改编范围、题材、受众和画风。
2. **M01 剧本分镜**：一次生成选题钩子、单集剧本、角色草案和 JSON 镜头，校对后同步到镜头与资产。
3. **角色一致性**：在外部平台生成并选定人物参考图；每次生成分镜时上传参考。ComfyUI 参数可选。
4. **M02 批量出图**：根据已接受分镜和角色生成中文自然语言图片词，逐镜复制到公开平台，回填满意的分镜图。
5. **M03 图生视频**：绑定选定分镜图，生成“一镜一动作”的动态提示词；首尾帧或动作驱动只在工作流真实支持时使用。
6. **回填与返修**：上传结果，记录实际用词、参数和问题时间点。失败片段进入 Q01，只修改主要问题。
7. **成片复盘**：人工选中可用片段，导出给剪辑；发布后通过 Q02 沉淀配方与表现数据。

旧版 D01–D06 数据仍保留；漫剧使用 M01–M03，AI 美女使用独立的快速创作卡。同步 M02/M03 会保留原镜头绑定的真实图片。

## 从零做一条 AI 美女作品

1. 切换 **AI 美女** Tab，创建项目。
2. 在 **人物库** 导入人物参考图，保存后点击 **用她创作**。没有参考图可先写人物形象词。
3. 在 **快速创作** 选择日常/穿搭/舞蹈，填一句话想法。
4. **组合基础图片词** 不需要 API；**生成 / 优化图片词** 可以调用已配置的文本模型，也可复制指令到外部对话平台再粘贴结果。
5. **保存并复制图片词**，到公开平台生成，并按平台能力上传人物/服装参考。
6. 回填图片，登记实际平台、用词和版本，人工检查后 **采用图片**。图片作品至此完成。
7. 视频可选：在已采用图片上生成视频词，到外部平台生成，再回填并采用视频。
8. 在 **作品与收藏** 中收藏模板，下次套用为新作品。

日常、穿搭和舞蹈是单条作品的玩法，同一人物可跨玩法复用。图片和视频分别记录采用版本；改动图片输入会清空待用视频词，旧版本和已选结果仍保留。旧人物项目统一归入 AI 美女，历史阶段可在作品页展开。

**视频参考**：素材库里打开视频，暂停到目标位置，点击提取当前帧，会保存截图与时间码来源记录。浏览器需支持视频编码，建议 MP4/H.264。图片模型只能分析抽到的画面，不能据此确认完整舞步、速度、音轨或原始提示词。

**舞蹈路线**：近似风格可用普通 I2V；精确跟随需要真实动作驱动视频和兼容工作流。Wan-Animate-2 的文字重点是外观与背景，不能用长篇文字替代驱动输入。

## 连接模型

点击左下角 **「模型连接设置」**：

| 设置 | 填写内容 |
|---|---|
| API Base URL | 兼容服务的地址，到 `/v1`，例如 `https://api.openai.com/v1` |
| 文本模型 | 服务实际支持的模型 ID |
| 视觉模型 | 可选，填写能接收图片的模型 ID；仅填名称不会让纯文本模型具备视觉能力 |
| API Key | 供应商密钥；本机免鉴权服务可留空 |

使用 OpenAI 兼容的 `/chat/completions` 接口，支持远程 HTTPS 与本机 HTTP。发送前会显示完整指令、所选来源和图片数量。接口请求最多等待 5 分钟；被截断或格式错误的返回保存为失败草稿，不能直接标记完成。

没有接入任何默认付费服务，也不会在打开项目时自动调用模型。API Key 不需要发给开发者。

## 搬到另一台电脑

**程序与创作数据分开保存：**

- 程序：从 GitHub 克隆，或下载源码 ZIP，解压后启动。
- 工程：在旧电脑点「工程备份」，把 ZIP 带到新电脑，在工作台点「恢复工程」。
- 模型密钥：在新电脑重新填写。

工程备份包含全部版本、来源、素材、试片、选择记录和模板修改。恢复会创建新项目，不覆盖已有项目；导入前会校验路径、文件大小和 SHA-256。

通常，上游接受版本变化会提醒下游复核。旧阶段结果及其下游被用于修订同一阶段时，会固定为历史快照，预览会标注，避免新结果依赖自身。资产和镜头可以在人工校对后勾选“改用上游最新接受版本”；历史记录仍然保留。

项目选择框旁的 `×` 可删除整个废弃项目，来源卡片和版本历史旁也有小删除按钮。删除项目必须输入完整项目名；当前采用版本和仍被下游引用的素材版本不能删除。

默认数据目录：`~/.ai-prompt-studio/data/`，Windows 对应 `%USERPROFILE%\.ai-prompt-studio\data\`。密钥位于同级的 `settings.json`，不会进入 Git 或工程备份。不要把自己的密钥写进素材备注或提示词正文——正文是工程数据，会随工程导出。

| 导出 | 包含什么 | 用途 |
|---|---|---|
| 工程备份 | `project.json`、全部素材、全部版本及试片记录 | 跨电脑恢复、个人备份 |
| 交接包 | `prompts.md`、`assets.md`、`shots.csv`、`manifest.json`、关联输入及所选图片/视频 | 公开平台出图、图生视频与人工剪辑 |

**交接包不是 ComfyUI workflow JSON，不能直接导入成节点工作流。** 它会列出缺项和版本差异，供复制提示词、挂图与后期交接。失败试片媒体不作为所选结果打包。

## 首版边界

- 单人、本机应用，只监听 `127.0.0.1`。不提供公网部署或多人同步。
- 文本按章节手工分段；漫画按页导入和校对；视频手工定位抽帧。尚无自动长篇分批执行、OCR、自动切镜或完整视频理解。
- 版本、依赖和采用记录可追溯。页面只检查字段与输入条件，不能保证叙事质量、人物一致性或视频合格。
- 单个素材最大 256 MB，恢复工程解压后最大 1 GB，每次最多 8 张、合计 20 MB 视觉输入。大量长视频建议先剪成镜头片段。
- 软件验证使用临时工程和模拟模型，不代表真实图片质量。先试一张人物图或三个短镜头，按目标平台的实际能力扩大生产。

## 开发与检查

后端使用 Python 标准库 HTTP、SQLite 与本地文件；前端使用原生 HTML/CSS/JavaScript，没有构建过程或运行时第三方依赖。

```bash
python3 checks/smoke.py
node --check web/app.js
node --check web/beauty.js
```

集成检查通过临时目录和模拟模型服务验证：并发编辑冲突、依赖过期、媒体范围读取、可投产条件、试片采用、ZIP 往返与路径攻击、密钥排除、模型输入快照、视觉请求和失败草稿保存。不会调用付费 API，也不修改个人工程。

可选浏览器检查需要安装 Google Chrome 和开发用的 Playwright（`pip install playwright`），运行 `python3 checks/browser.py`。它验证两套流程、Tab 隔离、基础图片词、外部结果粘贴、视觉提示词生成、图片/视频采用、收藏复用、工程恢复和移动端布局；不会接触个人工程或真实模型密钥。

2026-09-28 已在 macOS、Python 3.9 和 Chrome 上通过上述核心及浏览器检查。真实 ComfyUI 出片和 Windows/Linux 实机启动尚未验证。GitHub Actions 配置了 macOS / Windows / Linux，Python 3.9 / 3.12 的检查矩阵；运行状态以仓库 Actions 结果为准。
