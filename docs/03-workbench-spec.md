# 提示词工作台：产品与技术方案

状态：2026-09-28 已更新至 v1.1，入口为 `studio.py`。操作说明见 [AI 漫剧](04-drama-manual.md)、[AI 美女](05-beauty-manual.md)；本文的后续增强不是已实现功能。

当前实现 AI 漫剧 / AI 美女双 Tab、独立项目筛选、提示词生成、版本与依赖、媒体回填、收藏、工程恢复及交接导出。文本模型写提示词，用户在公开平台生成媒体；不调用生图 API。长篇按章节手工选择，漫画按页校对，视频手工抽帧；自动分批编排、OCR 和自动切镜尚未实现。

## 1. 产品定位

为个人创作者提供“带项目记忆的提示词生产工作台”：

- 输入小说、漫画、角色图或参考视频。
- 按阶段产出相互关联的剧本、资产设定、分镜和模型适配提示词。
- 输出可复制文本、挂图说明和镜头清单。
- 接收用户在公开平台或 ComfyUI 的生成结果，管理返修和可复用模板。

第一版以本地浏览器工作台为建议形态。生成图片/视频、剪辑和发布由用户现有工具完成。

## 2. 页面与操作

### 项目首页

顶部两个 Tab 分别显示项目和导航。漫剧首页展示五步生产线：剧本分镜、角色一致性、批量出图、图生视频、成片复盘。AI 美女只显示快速创作、人物库、作品与收藏；日常、穿搭、舞蹈属于每条作品的玩法。创建项目填写画幅、画风和时长，不强制绑定工作流档案。提示词默认中文自然语言。

首页显示“接下来做什么”和真实缺项，例如“EP001-S003 缺少首帧”，不使用无法解释的虚假完成度。

### 素材与定位

导入来源文本、图片、视频；文本按章节/段落管理，漫画按页/格校对，视频可手工指定片段时间。

选题、受众、前三秒钩子和画风作为 M01 的输入。素材来源和授权备注在详情中维护。

### 剧本与分镜

漫剧不再依次暴露素材分析、全剧规划、分集剧本、导演分镜等电影式工序。`M01` 在一次生成中输出选题定位、单集剧本、资产草案和 JSON 分镜；用户校对后同步为角色与镜头卡片。

`M02` 只优化批量图片提示词，`M03` 只优化图生视频提示词。支持生成当前阶段、手工修改、接受版本、回退、查看差异。不要求用户反复复制背景；阶段输入由工作台收集。

### 角色一致性与批量出图

角色、造型、场景、道具各有可见卡片，选定参考图在外部平台生成每镜时手工上传。LoRA、IP-Adapter 和 ControlNet 等放在可选设置中。每镜一张出图卡，包含剧情目的、静态时刻、构图、图片提示词和首帧绑定。

主要操作：批量复制图片词、绑定人工选中的分镜图、查看缺项。可编辑结构化字段和最终正文，保留修改记录。

### 图生视频与成片复盘

图生视频页面集中展示每镜起点、动作、落点和短视频提示词。提示词正文中不展示内部 ID、JSON、节点参数或说明文字；这些放在相邻的镜头信息和交接区。

对比同镜不同生成版本，记录问题时间点、采用/返修原因。选定某个结果后才进入剪辑包。

成功组合可以另存配方，注明适用模型、参考素材条件、动作范围。发布表现先手工登记到作品，不自动代发。

模板与模型档案放在设置中。模板可编辑、版本可恢复；普通用户不需要理解 Agent 编排。

### AI 美女快速创作

左栏为人物、玩法、想法、平台和可选参考；右栏为可编辑图片词和可选视频词；下方直接回填结果。基础图片词本地组合，B04 用于文本/视觉模型优化，生成前预览；也支持复制指令并粘贴外部结果。

采用图片即完成图片作品。视频词以已检查图片为起点，保留 `video_source` 版本与 `bindings.first_frame`。改图片输入清除待用视频词，旧版本保留；换选图片后提示复核旧视频词。

旧 `daily/outfit/dance` 项目不迁移或删除数据，前台统一归入美女 Tab。旧镜头可在新界面继续编辑，旧阶段全文可在作品页查看。

## 3. 最小功能范围

| 范围 | 首版实现 | 后续增强 |
|---|---|---|
| 文本素材 | 粘贴、TXT/Markdown、手工章节校正 | EPUB/PDF/DOCX 自动解析 |
| 漫画 | 有序图片、逐页视觉分析、校对对白/说话人/来源 | 自动分格及复杂阅读顺序识别 |
| 参考视频 | 上传、时间范围、关键帧与人工校正后的分析表 | 自动切镜、动态采样、直接视频理解 |
| AI 内容生成 | 文本模型+可选视觉模型；阶段生成和失败恢复 | 更丰富的供应商适配 |
| 无 API 使用 | 导出流程指令，在现有对话工具执行，再导入/编辑结果 | 不依赖第三方工具的本地模型体验 |
| 漫剧链路 | M01 剧本与 JSON 分镜、角色一致性、M02 批量出图词、M03 图生视频词 | 批量跨集制作 |
| 人物链路 | 人物库、单条三玩法创作、图片完成/视频可选、回填和收藏 | 更复杂的多角色及商品系列 |
| 平台交接 | 复制文本、手工上传参考、记录实际平台及结果 | 用户明确需要时再接入生成 API |
| 闭环 | 版本、引用、受影响项提示、配方、手工表现记录 | 自动质量辅助判断 |
| 数据 | 本地持久化、导出和恢复 | 多人协作与云同步 |

自动视频分析不是“网页上传就能看懂”：必须有兼容的视觉模型。仅支持图片输入时，抽帧分析要标明覆盖范围，不能假装具有完整视频理解能力。没有视觉模型时保留人工描述和关键帧校对入口。

## 4. 一次阶段生成如何完成

1. 收集当前阶段输入：项目规则、已接受的上游版本、相关来源片段、绑定资产和模型档案。
2. 明确用户本次范围，例如“EP001 的 S003”，不自动扩大为全剧重写。
3. 使用对应流程模板请求语言/视觉模型，返回结构化草稿。
4. 校验字段、ID 引用、来源覆盖、镜长以及模型能力。模型输出视为不可信数据，来源文本中的指令不会改变工作台权限。
5. 草稿可编辑、可接受；不自动覆盖已接受版本。
6. 保存模板版本、模型名称、输入版本和生成结果。被截断或格式错误的结果保留为失败草稿，不能标记完成。
7. 长文按章节/集处理，保存已处理范围和未处理范围；恢复时从检查点继续。

模型对作品的创作判断与程序校验分开：程序能查“引用丢失”，不能保证“故事好看”。

## 5. 数据设计

建议使用 SQLite 保存结构化状态、本地文件夹保存素材。**数据库是应用阶段内容的唯一权威来源，Markdown/CSV/JSON 是导出物。** 外部修改通过显式导入形成新版本，不做暗中的双向同步。

| 对象 | 核心字段 |
|---|---|
| `Project` | id、track、format、style、scope、active_profile |
| `Source` | id、project_id、media_type、relative_path、hash、locator、extracted_content |
| `Artifact` | id、project_id、episode_id、kind、revision、content、review_status、depends_on |
| `MediaAsset` | id、project_id、kind、relative_path、hash、selection_status、metadata |
| `Attempt` | id、shot_id、prompt_revision、profile_revision、actual_inputs、actual_parameters、result_asset_ids、judgment、feedback |
| `Template` | id、kind、revision、body、variables、output_contract、compatible_profiles |
| `Publication` | id、project_id、selected_attempt_ids、published_at、observations |

角色、造型、剧本、分镜、提示词和配方先作为不同 `Artifact.kind`，内容放 JSON；确有查询瓶颈再拆专表。`depends_on` 必须引用明确版本，不能只引用“最新角色”。

`review_status`：`draft / accepted / needs_review`。另设素材缺项和引用过期标记，不把十几种互相重叠的状态塞进一个枚举。

公开平台提示词检查以文字、已确认版本和必要参考为主；无 ComfyUI 档案不阻塞写词或完成图片作品。绑定 ComfyUI 档案的旧流程继续检查已验证能力和输入槽。字段检查不等于真实出片质量验证。

AI 美女复用 `asset`（人物）、`shot`（单条作品）、`attempt`（生成尝试）、`recipe`（收藏）版本模型，不引入第二套数据库。`attempt.medium` 区分图片/视频；选择事件也带 medium，分别计算 `selected_images` 与 `selected`。旧事件默认 video，备份继续兼容 schema 1。

生成尝试判定：`unreviewed / accepted / rejected`。镜头交付完成要求选定一个实际可用结果；“提示词已复制”不等于视频已经生成。

### 版本变更规则

- 编辑接受版本时生成新修订，不原地覆盖。
- 下游保存上游版本快照；更新上游后，计算引用关系并提示受影响项。
- 如果采用新的角色基准，引用旧基准的镜头标记需复核；已完成的历史作品仍保留原结果。
- 用户可以决定保留历史镜头，也可以逐镜重新生成；不要无条件重跑所有下游。
- 外部生成前修改了提示词或参考图，回填时登记实际值，防止结果错误归因给原版本。
- 恢复旧版本也作为新的选择记录，不能删除中间尝试。

## 6. 可选 ComfyUI 模型档案

档案应由用户当前能跑通的工作流提取并核对，不按模型名凭空假定节点能力。

建议字段：

```json
{
  "id": "local-workflow-01",
  "revision": 1,
  "name": "用户现有工作流",
  "workflow_file": null,
  "workflow_hash": null,
  "checkpoint": null,
  "mode": "unknown",
  "prompt_language": "zh",
  "prompt_style": "unverified",
  "capabilities": {
    "first_frame": null,
    "last_frame": null,
    "multiple_references": null,
    "driving_video": null,
    "pose_input": null,
    "negative_prompt": null,
    "audio": null
  },
  "input_slots": [],
  "frame_count_rule": null,
  "tested_settings": null,
  "verification": "unverified"
}
```

`null` 表示未知，不表示支持。档案包含生成模型、LoRA/文本编码器等可用版本信息，但只有实际读取或用户提供的值才写入。

| 档案模式 | 提示词输出规则 |
|---|---|
| 通用草稿 | 输出镜头意图，列出待确认能力；不标“已适配” |
| 普通 I2V | 以首帧为基础描述动作、摄影和结果；保持已有外观 |
| 首尾帧 | 只有该工作流实际接受尾帧时，分别提供首帧、尾帧和过渡描述 |
| 初代 Animate | 按其动作驱动和预处理输入规则给出素材说明及兼容正文 |
| Animate-2 | 依官方示例和实际节点，优先人物外观/背景描述，动作由驱动视频提供 |

动作分段秒数可以作为导演意图，但精确执行仍需模型控制能力。帧数、生成尺寸和时长必须满足真实工作流规则，不能默认“任意秒数×任意 FPS”都可运行。

导出文件是交接清单，**不宣称可以作为 ComfyUI workflow JSON 直接导入**。第一版不猜节点 ID，也不自动修改用户工作流。

## 7. 导出与回填

一个镜头交接包包含：

- `prompts.md`：逐镜可复制文本，明确标记草稿/可投产。
- `shots.csv`：镜号、顺序、时长、角色、起止状态、素材说明、后期备注。
- `manifest.json`：镜号、修订、模型档案及资产关联，用于交接与追溯。
- 关联输入与所选实际结果随包携带；完整恢复使用独立的“工程备份”，其中包含 `project.json` 和全部素材。

命名建议：`项目_EP001_S003_prompt-v002_take-003.mp4`。实际导入以 manifest 或用户选择绑定，不只靠文件名猜测。

回填失败结果时先保留证据，再给出最小修改建议。没有视频输入只收到描述时，界面显示“按描述分析”，不能显示“视频检查通过”。

## 8. 技术实现建议

实际采用原生 HTML/CSS/JavaScript 前端，Python 标准库 HTTP + SQLite 后端，本地素材目录。相比原先建议的 React/FastAPI，首版不需要依赖安装或构建，方便搬到另一台电脑。视频关键帧通过浏览器原生解码与 Canvas 提取，不依赖 FFmpeg。

最初一个本地服务即可，不引入微服务、Redis、向量数据库、通用 Agent 框架或工作流画布引擎。阶段路由用明确的函数和模板映射实现；已有阶段和引用查询足以支持第一版。

语言模型接入先支持一个常用兼容协议；视觉模型使用相同服务或独立配置。没有 API 时可使用“导出流程指令→外部对话执行→导入结果”路径，避免伪装成已经接通自动生成。

本地服务默认只监听 `127.0.0.1`。密钥存项目外的私有设置，不进入提示词、导出包或日志。外部模型调用时显示实际发送的素材范围；本地保存不等于离线推理。

素材导入限制在用户选择的文件/项目目录；服务不允许用任意路径读取电脑文件。备份使用数据库一致性备份及对应素材清单，恢复先验证关联完整性。

## 9. 开发顺序

| 阶段 | 可验收结果 |
|---|---|
| 内容小样 | 本轮模板完成三个关联镜头；用户在当前 ComfyUI 实测一次并回填 |
| 工作台骨架 | 新建/恢复项目、素材管理、阶段编辑、模板导出与结果导入 |
| 自动生成 | 接入一个文本模型、一个可选视觉模型；阶段输出校验与检查点 |
| 两条产线 | 漫剧完整阶段；日常/穿搭/舞蹈模板分流；模型档案适配 |
| 闭环验证 | 同镜多版本、最小返修、下游复核提示、配方与剪辑包 |

先用短样片验证模板，不用投入全剧生成成本来测试软件。

## 10. 首版验收场景

1. 导入一段小说，得到带来源位置的剧本、资产和三个关联镜头。
2. 导入漫画页，说话人不明确时显示未决项，能够手工校正。
3. 输入长篇素材，明确显示已分析范围，断开后恢复，不冒充已读完整部。
4. 改一套服装，只提示复核引用该服装版本的镜头；旧版可查看。
5. 缺首帧或模型能力未知时仍能导出草稿，但不显示可投产。
6. 不支持尾帧/负面提示词的档案，不生成可复制的对应字段。
7. 给参考视频和人物图，选择“精确动作复现”后列出驱动输入；不能只交一段文案就宣称复现。
8. 回填同镜两次失败、一次成功，三次实际输入和结果都能追溯。
9. 视频内容未被视觉模型或人实际检查时，不出现“检测通过”。
10. 重启工作台后项目、素材和采用版本仍在；导出再导入不丢关联。
11. 一个作品的发布指标能关联所采用镜头版本，零分母显示暂无数据。
12. 剪辑包只包含所选版本；缺文件、过期引用和未选镜头明确列出。

这是设计验收场景列表。程序检查见 `checks/smoke.py`；真实素材的创作质量与 ComfyUI 出片效果需要在用户的实际工作流中验证，不能由模拟模型测试代替。
